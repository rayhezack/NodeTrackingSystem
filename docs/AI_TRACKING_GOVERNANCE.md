# AI 埋点设计工作流与复用约束

## 实际调用链

专用 Skill 源文件是 `skills/pollo-tracking-design/SKILL.md`，规则与输出协议在其 `references/` 下。修改这些 Markdown 后运行 `npm run skill:tracking:prepare`，将原文打包到 `shared/tracking-skill.generated.ts`。构建前自动生成，测试及提交前校验源文件和产物一致。

`shared/pollo-tracking-policy.ts` 的 `loadTrackingDesignSkill(stage)` 仅按阶段加载主文件、复用契约和阶段协议；Worker 与 NestJS 共用此装配器。模型请求的 system message 包含实际 Skill 文件内容及源文件哈希，user message 包含 PRD、正式库和当前阶段业务数据。正式规则不再手写在 TypeScript 提示词里。

1. 读取需求 PRD、附件、现有设计及当前端的完整正式事件、参数、公共属性和枚举表。
2. `generateReusePlan` 规划直接复用、扩枚举、补可选参数或新增事件，校验正式来源与生命周期。
3. `generateDesignBatches` 按事件生成设计；阶段提示词来自 `designPrompt`，校验失败最多修正一次。
4. `enforceGovernance` 将复用元数据固定为正式库原文，保存治理报告及正式库指纹。
5. 应用前重新读取正式库，验证版本与指纹，并使用重新治理后的结果写入设计工作台及设计参数表。

## 复用边界

- 正式事件的名称、定义、触发时机、适用端、处理方、公共属性、版本、最低版本和指标场景不得由模型覆盖；正式空值也不得臆测补齐。
- 正式参数的定义、示例、适用端保留原值；类型、必传规则、条件冲突会拒绝草稿。正式参数未提供独立默认值，AI 提议的默认值不得自动生效。
- 枚举取值是正式值与新增值的并集，不能通过模型输出删除原值。复用事件新增参数只能为可选参数。
- 需求特有内容分别写入事件 `requestNotes` → 工作台“本次需求补充说明”，参数 `requestNotes` → 设计参数表“本次需求说明”。
- 模型改写元数据时，代码保留正式值，差异以“AI 提议、待确认、不改变正式口径”转入说明，不视为获批的实现要求。业务语义冲突仍需人工确认。
- 生成和应用都执行相同约束。`official-first-v3` 拒绝旧版草稿，要求重新生成；历史已经应用的设计不自动改写。

## 开发交接

“复制整份需求开发说明”导出已保存的同需求全部事件和参数、各流程字段、参与人、设计素材引用、Base 链接、待确认项与实施检查表。Markdown 内含结构化 JSON。任何事件/参数读取失败都会停止复制，避免不完整上下文；剪贴板失败则提供完整文本手动复制。PRD 全文和图片二进制不内嵌。

## Base 字段

App 与 Web 设计工作台均增加文本字段“本次需求补充说明”；正式事件库与正式参数库不增加需求专属字段。
